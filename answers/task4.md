# Task 4：思考题

## 1. Make 和简单的 `build.sh` 有什么区别？

`build.sh` 是把所有 `gcc` 命令按顺序写一遍，每次运行都会从头编译所有文件，不管有没有改动。

`make` 会根据 `Makefile` 里的依赖关系，只重新编译发生变化的目标。比如只改了 `src/calculator.c`，`make` 就只会重新生成 `calculator.o` 并重新链接，不会动 `main.o` 和 `logger.o`。这样在大项目里能省很多时间。

另外 `make` 本身也成了一种描述构建规则的方式，比手写 shell 脚本更清晰、更容易维护。

## 2. CMake 是编译器吗？执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

CMake 不是编译器，它只是一个**构建系统的生成器**。它读入 `CMakeLists.txt`，生成 `Makefile` 或 `Ninja` 等构建文件，然后交给真正的构建工具去执行。

执行 `cmake --build build` 时，最终还是在调用 `make` 或 `ninja`，而它们会调用 `gcc`（或其他 C 编译器）来编译 `.c` 文件。所以真正编译 C 源文件的依旧是 `gcc`。

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

因为编译很花时间。一个项目如果有几十、几百个 `.c` 文件，全量编译可能要几分钟甚至几十分钟。

如果只修改了一个 `.c` 文件，而 `make` 能识别出其他 `.o` 文件没有变化，就只需要重新编译那个改过的文件，再重新链接一次。这样从修改到测试的反馈会快很多，也不会浪费 CPU 资源。
