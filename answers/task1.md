# Task 1：从 C 源码到可执行文件

一个 `.c` 文件要经过四个阶段才能变成可以直接运行的可执行文件：**预处理 → 编译 → 汇编 → 链接**。下面是我自己跑了一遍 gcc 命令后记的笔记。

## 1. 预处理

这一步把所有 `#` 开头的指令处理掉：

- `#include` 引入的头文件内容被复制进来
- `#define` 的宏被替换（也就是宏展开）
- 注释会被删掉

我在 WSL 里写了一个最简的 `hello.c`，里面用了一个 `#define GREET "hello"`，然后跑 `gcc -E hello.c -o hello.i`。处理完之后用 `wc -l hello.i` 看，**行数暴涨了很多**。再用 `grep GREET hello.i` 找一下，`GREET` 已经变成 `"hello"` 了。

虽然文件变大了很多，但 `.i` 文件里的内容**还是 C 代码**，不是汇编，也不是二进制。

## 2. 编译

编译器把预处理后的 C 代码翻译成汇编代码，产物是 `.s` 文件。我打开 `hello.s` 看了一下，里面是 `mov`、`call` 这种汇编指令。

这一阶段也做语法检查——**语法错误（漏分号、类型不匹配、变量没声明）都是在这里报错的**。所以平时写代码编译失败，先看这一步的报错。

## 3. 汇编

汇编器把 `.s` 变成机器码，产物是 `.o`（目标文件）。我跑完 `gcc -c hello.s -o hello.o` 后用 `cat hello.o` 看文件，**全是乱码**——说明 `.o` 已经是二进制了。

虽然 `.o` 里有机器指令，**但还不能直接跑**。因为它里面调用的函数地址还是占位的，要等所有 `.o` 凑齐后由链接器统一处理。

## 4. 链接

链接器把多个 `.o` 和系统库拼在一起，解决"谁调用了谁"的地址问题，得到最终的可执行文件。

用 `gcc hello.o -o hello`（或者直接 `gcc hello.c -o hello`）跑完，就可以直接 `./hello` 运行了。

这一步最常见的报错是 **undefined reference**——某个函数只声明没实现，或者库没链上。

## 总结

整个过程我觉得可以把它比喻成**翻译一本书**：

- 预处理 → **排版**：清理注释、展开宏、把引用的内容插进正文
- 编译 → **逐句翻译**：从 C 翻成汇编
- 汇编 → **排成印刷字体**：让机器看得懂
- 链接 → **把引用的其他书合订进来**：补全互相引用的内容

四步缺一不可，每一步的产物都直接喂给下一步。
